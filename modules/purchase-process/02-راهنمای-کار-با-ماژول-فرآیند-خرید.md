# راهنمای کار با ماژول فرآیند خرید

**مخاطب:** توسعه‌دهنده و مدیر فنی که داخل storage کد می‌نویسد  
**پیش‌نیاز:** مطالعه سند `01-ماژول-فرآیند-خرید.md`  
**محیط هدف:** وردپرس + ووکامرس + پلاگین EzLens Secure Login

---

## ۱. مدل ذهنی قبل از نوشتن کد

قبل از باز کردن ادیتور، این سه جمله را بپذیرید:

1. **اینجا snippet می‌نویسم، نه پلاگین.**
2. **هر فایل = یک مسئولیت.**
3. **اگر این فایل خراب شود، ممکن است کل سایت ۵۰۰ شود.**

| فکر اشتباه | فکر درست |
|-------------|----------|
| «یک پلاگین کوچک داخل storage می‌سازم» | «یک قابلیت مشخص به خرید اضافه می‌کنم» |
| «چند صفحه و چند AJAX و تنظیمات با هم» | «حداکثر یک موضوع: سبد یا محصول یا قانون» |
| «نام تابع عمومی بگذارم» | «همه چیز با پیشوند `ezp_`» |
| «بعداً تست می‌کنم، اول فعال کنم» | «اول غیرفعال ذخیره، بعد تست، بعد فعال» |

---

## ۲. ورود به پنل ماژول

1. وارد پیشخوان وردپرس شوید.
2. به بخش مربوط به EzLens / فرآیند خرید بروید (لیست فایل‌ها).
3. دو عمل اصلی دارید:
   - **افزودن فایل جدید**
   - **ویرایش فایل موجود**

### فیلدهای مهم هنگام ذخیره

| فیلد | الزامی | توضیح |
|------|--------|--------|
| عنوان نمایشی | بله | فارسی آزاد — فقط برای پیدا کردن در لیست (مثلاً «سبد خرید») |
| نام فایل (انگلیسی) | بله (فقط هنگام ایجاد) | فقط `a-z` `0-9` `-` `_` — مثال: `custom-cart` |
| توضیحات | خیر | یادداشت برای خودتان/تیم |
| کد PHP | بله | محتوای اجرایی |
| وضعیت فعال | اختیاری | تا وقتی مطمئن نیستید خاموش بماند |

### قوانین نام فایل

- پسوند `.php` خودکار اضافه می‌شود.
- بعد از ایجاد، **نام فایل قفل است** (عمدی).
- اگر نام تکراری باشد → **خطا** (rename خودکار نداریم).
- عنوان نمایشی را هر وقت می‌توانید عوض کنید؛ روی فایل فیزیکی اثر ندارد.

## ۳. اسکلت استاندارد هر فایل storage

هر فایل جدید را از این قالب شروع کنید:

```php
<?php
/**
 * عنوان نمایشی: مثال — سبد خرید سفارشی
 * نام فایل: custom-cart
 * مسئولیت: فقط سبد خرید
 */

if ( ! defined( 'ABSPATH' ) ) {
	exit;
}

if ( ! function_exists( 'ezp_example_feature_boot' ) ) {

	/**
	 * نقطه ورود این قابلیت
	 */
	function ezp_example_feature_boot() {
		// ثبت شورت‌کد یا هوک
	}

	add_action( 'init', 'ezp_example_feature_boot', 20 );
}

// اگر شورت‌کد دارید:
if ( ! function_exists( 'ezp_example_shortcode' ) ) {
	add_shortcode( 'example_shortcode', 'ezp_example_shortcode' );

	function ezp_example_shortcode( $atts = array() ) {
		if ( ! function_exists( 'WC' ) ) {
			return '';
		}
		// ...
		return '';
	}
}
```

### الزامات اجباری

1. چک `ABSPATH`
2. پیشوند `ezp_` برای توابع، اکشن‌ها، شورت‌کدهای اختصاصی
3. `function_exists` دور تعریف توابع
4. وابستگی‌ها با `function_exists` / `class_exists` محافظت شوند
5. بدون `Plugin Name` و بدون activation hook

## ۴. انواع فایل پیشنهادی

| نوع | نام فایل نمونه | محتوا | ممنوع |
|-----|----------------|--------|--------|
| صفحه/شورت‌کد | `product-page.php` | UI + شورت‌کد | منوی ادمین |
| سبد خرید | `custom-cart.php` | شورت‌کد سبد + AJAX همان قابلیت | منطق چک‌اوت کامل مگر لازم |
| قانون خرید | `cart-rules.php` | فیلتر قیمت/محدودیت | HTML بزرگ |
| کمکی مشترک | `ezp-helpers.php` | توابع خیلی کوچک مشترک | منطق تجاری سنگین |

**پیشنهاد نام‌گذاری:**

```text
product-page.php
custom-cart.php
checkout-note.php
shipping-message.php
```

## ۵. شورت‌کد در برابر هوک

### چه وقت شورت‌کد؟

وقتی خروجی باید داخل صفحه/بلوک قرار بگیرد:

```text
[custom_product_page]
[custom_cart]
```

صفحه را در وردپرس بسازید، شورت‌کد را بگذارید، و در تنظیمات ووکامرس آن صفحه را به سبد/محصول وصل کنید (در صورت نیاز).

### چه وقت هوک/فیلتر؟

وقتی می‌خواهید رفتار پیش‌فرض را تغییر دهید بدون صفحه جدید:

```php
add_filter( 'woocommerce_add_to_cart_validation', 'ezp_validate_cart_item', 10, 3 );
add_action( 'woocommerce_before_cart', 'ezp_cart_notice' );
```

## ۶. قوانین کدنویسی اختصاصی این ماژول

### ۶.۱ نام تابع

```php
// خوب
function ezp_cart_render() {}
function ezp_product_page_gallery() {}

// بد — احتمال تداخل بالا
function render() {}
function custom_product_page_render() {}  // اگر فایل دوم هم همین را داشته باشد → Fatal
```

> اگر از روی کد قدیمی کپی می‌کنید که تابع بدون پیشوند دارد، قبل از فعال‌سازی نام را عوض کنید یا `function_exists` بگذارید.

### ۶.۲ جلوگیری از redeclare

همیشه:

```php
if ( ! function_exists( 'ezp_something' ) ) {
	function ezp_something() {}
}
```

Loader هم قبل از include نام توابع را بررسی می‌کند؛ ولی خودتان هم باید رعایت کنید.

### ۶.۳ وابستگی ووکامرس

```php
if ( ! function_exists( 'WC' ) || ! WC()->cart ) {
	return '<div>ووکامرس در دسترس نیست.</div>';
}
```

### ۶.۴ AJAX

- اکشن یکتا با پیشوند: `ezp_cart_update_qty`
- هم برای لاگین و هم مهمان در صورت نیاز: `wp_ajax_` و `wp_ajax_nopriv_`
- همیشه `check_ajax_referer`
- پیام خطا/موفقیت واضح به فارسی

### ۶.۵ استایل و اسکریپت

- برای snippetهای UI، CSS/JS اینلاین یا شرطی قابل قبول است.
- انتخابگرها را با پیشوند محدود کنید (مثلاً `.ezp-pp` یا `.ezc-wrap`) تا با تم تداخل کم شود.
- در موبایل/تبلت، breakpoint واقعی بنویسید؛ فقط «یک ستون کردن» کافی نیست.

## ۷. چک‌لیست قبل از فعال‌سازی

قبل از زدن دکمه فعال، این لیست را طی کنید:

- [ ] فایل فقط یک مسئولیت دارد؟
- [ ] همه توابع با `ezp_` و داخل `function_exists` هستند؟
- [ ] نام فایل انگلیسی و یکتاست؟
- [ ] شورت‌کد/اکشن با چیز دیگری تداخل لفظی ندارد؟
- [ ] وابستگی به ووکامرس/کلاس دیگر با چک وجود دارد؟
- [ ] روی محیط تست یک‌بار صفحه مربوطه باز شده؟
- [ ] در صورت خطا، می‌دانید چطور از دیتابیس `status=0` کنید؟

### بازیابی اضطراری اگر سایت ۵۰۰ شد

در phpMyAdmin:

```sql
-- همه snippetها را خاموش کن
UPDATE {prefix}ezlens_purchase_scripts SET status = 0;

-- یا فقط یک فایل
UPDATE {prefix}ezlens_purchase_scripts
SET status = 0
WHERE filename = 'product-page.php';
```

سپس صفحه را رفرش کنید و فایل مشکل‌دار را ویرایش کنید.

## ۸. سناریوهای عملی

### سناریو A — صفحه محصول سفارشی

1. فایل جدید: عنوان `صفحه محصول` / نام فایل `product-page`
2. شورت‌کد: `[custom_product_page]`
3. کد را ذخیره کنید (غیرفعال)
4. در یک برگه تست شورت‌کد را بگذارید
5. اگر درست بود فعال کنید
6. در صورت نیاز، قالب تک‌محصول را به همان برگه/شورت‌کد هدایت کنید

### سناریو B — سبد خرید سفارشی

1. فایل: عنوان `سبد خرید` / نام فایل `custom-cart`
2. شورت‌کد: `[custom_cart]`
3. برگه سبد خرید ووکامرس را با این شورت‌کد جایگزین یا هم‌راستا کنید
4. AJAX تعداد/حذف/کوپن را روی محیط واقعی تست کنید

### سناریو C — دو فایل و یک تابع تکراری

اگر هر دو فعال باشند و یک نام تابع مشترک داشته باشند:

1. سایت ممکن است Fatal بدهد
2. هر دو را غیرفعال کنید
3. نام توابع را یکتا کنید
4. یکی‌یکی فعال کنید

## ۹. مثال خوب در برابر مثال بد

### خوب

```php
<?php
if ( ! defined( 'ABSPATH' ) ) {
	exit;
}

if ( ! function_exists( 'ezp_free_shipping_notice' ) ) {
	add_action( 'woocommerce_before_cart', 'ezp_free_shipping_notice' );

	function ezp_free_shipping_notice() {
		if ( ! function_exists( 'WC' ) || ! WC()->cart ) {
			return;
		}
		echo '<div class="ezp-note">برای سفارش‌های بالای ۵۰۰ هزار تومان ارسال رایگان است.</div>';
	}
}
```

### بد

```php
<?php
/*
Plugin Name: My Cart System
*/
function render() { // بدون پیشوند
	include __DIR__ . '/admin.php'; // ساختار پلاگین
	create_tables(); // نصب داخل snippet
}
render();
```

## ۱۰. ویرایش فایل موجود

1. از لیست، ویرایش را باز کنید (باید با دسترسی ادمین باز شود).
2. عنوان و توضیح را آزادانه تغییر دهید.
3. نام فایل را تغییر ندهید (قفل است).
4. کد را ذخیره کنید.
5. اگر فایل فعال است، بعد از ذخیره سنگین، یک‌بار فرانت را چک کنید.

اگر دکمه ویرایش «اجازه دسترسی ندارید» داد، معمولاً به‌خاطر slug اشتباه منو بوده؛ در نسخه‌های اصلاح‌شده لینک ویرایش روی صفحه ثبت‌شده add+id تنظیم شده است.

---

## ۱۱. ارتباط با فایل‌های آماده پروژه

| فایل آماده | شورت‌کد | موضوع |
|------------|---------|--------|
| `ezlens-custom-product-page.php` | `[custom_product_page]` | صفحه محصول ریسپانسیو + ویژگی کشویی |
| `ezlens-custom-cart-page.php` | `[custom_cart]` | سبد خرید AJAX |

این فایل‌ها را به‌عنوان snippet داخل storage وارد کنید (با نام فایل انگلیسی یکتا)، نه به‌عنوان پلاگین جدا.

---

## ۱۲. اشتباهات رایج و راه حل

| مشکل | علت محتمل | کار سریع |
|------|-----------|----------|
| سایت ۵۰۰ شد | Fatal در فایل فعال | `status=0` در دیتابیس |
| Cannot redeclare ... | دو تابع هم‌نام | یکی را غیرفعال/تغییر نام |
| جدول آماده نیست | نصب/حروف بزرگ‌کوچک WAMP | Install خودترمیم / نسخه اصلاح‌شده |
| ویرایش باز نمی‌شود | slug منو | از لینک اصلاح‌شده add&id استفاده شود |
| فایل تکراری ساخته شد | rename قدیمی | الان باید خطا بدهد؛ نسخه ماژول را به‌روز کنید |
| شورت‌کد چیزی نشان نمی‌دهد | فایل غیرفعال یا WC نیست | وضعیت و وابستگی را چک کنید |

## ۱۳. گردش کار پیشنهادی تیم

```text
1. درخواست قابلیت (مثلاً پیام سبد)
2. ایجاد فایل با نام انگلیسی یکتا (غیرفعال)
3. پیاده‌سازی با قالب استاندارد
4. تست روی لوکال / استیج
5. فعال‌سازی روی پروداکشن
6. مانیتورینگ ۳۰ دقیقه اول (خطا/لاگ)
```

هرگز روی پروداکشن مستقیم فایل ناشناس را فعال نکنید.

---

## ۱۴. خلاصه دستورالعمل یک‌صفحه‌ای

1. Snippet بنویس، پلاگین نه.  
2. یک فایل = یک کار.  
3. پیشوند `ezp_` + `function_exists`.  
4. عنوان فارسی جدا، نام فایل انگلیسی ثابت.  
5. تکراری نساز؛ خطا را جدی بگیر.  
6. اول ذخیرهٔ خاموش، بعد تست، بعد فعال.  
7. اگر سایت خوابید: همه `status=0`.
