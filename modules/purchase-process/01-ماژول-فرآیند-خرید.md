# ماژول فرآیند خرید (Purchase Process)

**پلاگین مادر:** EzLens Secure Login  
**مسیر ماژول:** `modules/purchase-process/`  
**نسخه مرجع مستند:** ۱.۵+  
**مخاطب:** مدیر فنی، توسعه‌دهنده، پشتیبان ایزی‌لنز

---

## ۱. این ماژول چیست؟

ماژول **فرآیند خرید** یک مدیر اسکریپت PHP داخل پلاگین EzLens Secure Login است.

شبیه **Code Snippets** عمل می‌کند، با این تفاوت که:

- مخصوص **شخصی‌سازی منطق خرید و فروشگاه** طراحی شده
- فایل‌ها در پوشه امن `storage` نگه‌داری می‌شوند
- وضعیت فعال/غیرفعال در دیتابیس ثبت می‌شود
- Loader فقط فایل‌های فعال را روی سایت اجرا می‌کند

### هدف اصلی

شخصی‌سازی رفتار خرید **بدون دست‌کاری هسته پلاگین، تم Woodmart، یا هسته ووکامرس**.

نمونه‌های استفاده واقعی در ایزی‌لنز:

| قابلیت | مثال |
|--------|------|
| صفحه محصول سفارشی | شورت‌کد `[custom_product_page]` |
| سبد خرید سفارشی | شورت‌کد `[custom_cart]` |
| قوانین سبد / محدودیت تعداد | فیلتر و هوک ووکامرس |
| فیلد یا پیام سفارشی در خرید | منطق PHP سبک |

---

## ۲. چه چیزی نیست؟

این ماژول **پلاگین‌ساز** نیست.

| نباید انجام شود | دلیل |
|------------------|------|
| ساخت منوی ادمین پیچیده داخل storage | خارج از محدوده snippet |
| ساخت جدول دیتابیس جدید در فایل storage | نصب/اسکیما فقط در خود ماژول |
| سیستم لایسنس / آپدیت | مربوط به هسته پلاگین |
| چند CPT و REST API بزرگ | باید ماژول رسمی جدا باشد |
| کپی‌برداری از ساختار کامل یک پلاگین | تداخل و Fatal ایجاد می‌کند |

**قانون طلایی:**  
هر فایل storage فقط باید یک «قابلیت مشخص» به فروشگاه اضافه کند — نه یک سیستم کامل.

## ۳. معماری ماژول

```
modules/purchase-process/
├── class-install.php      # نصب جدول، پوشه storage، خودترمیمی
├── class-ajax.php         # ذخیره / حذف / لیست / اعتبارسنجی کد
├── class-loader.php       # بارگذاری فایل‌های فعال روی سایت
├── DEVELOPER.md           # راهنمای توسعه‌دهنده (در صورت وجود)
├── admin/
│   ├── assets/            # CSS/JS پنل ادمین
│   └── pages/
│       ├── list.php       # لیست فایل‌ها
│       └── edit.php       # افزودن / ویرایش فایل
└── storage/
    ├── .htaccess          # مسدودسازی دسترسی مستقیم وب
    └── *.php              # فایل‌های snippet فعال/غیرفعال
```

### نقش هر بخش

| بخش | نقش |
|-----|-----|
| **Install** | ساخت/بررسی جدول، ساخت پوشه storage، تشخیص جدول روی ویندوز/لینوکس |
| **Ajax** | CRUD فایل‌ها با nonce و `manage_options` |
| **Loader** | در `init` اولویت ۲۰ فایل‌های `status=1` را include می‌کند |
| **Admin UI** | مدیریت انسانی فایل‌ها (عنوان، نام فایل، کد، وضعیت) |
| **Storage** | محل فیزیکی کدهای اجرایی |

## ۴. دیتابیس

جدول پیش‌فرض (با در نظر گرفتن `$wpdb->prefix`):

```text
{prefix}ezlens_purchase_scripts
```

### فیلدهای مهم

| فیلد | توضیح |
|------|--------|
| `id` | شناسه یکتا |
| `title` | عنوان نمایشی (فارسی آزاد) |
| `filename` | نام فایل فیزیکی انگلیسی (مثلاً `product-page.php`) |
| `description` | توضیح اختیاری |
| `status` | `1` = فعال ، `0` = غیرفعال |
| `created_at` / `updated_at` | زمان‌ها |

### نکات حیاتی

1. **عنوان نمایشی ≠ نام فایل**  
   عنوان می‌تواند «صفحه محصول» باشد؛ نام فایل باید `product-page.php` بماند.

2. **نام فایل بعد از ایجاد قفل است**  
   برای جلوگیری از یتیم شدن فایل روی دیسک و تداخل مسیر.

3. **فایل تکراری پذیرفته نمی‌شود**  
   اگر همان `filename` وجود داشته باشد، سیستم خطا می‌دهد و rename خودکار انجام نمی‌دهد.

4. **حساسیت حروف در ویندوز/WAMP**  
   در برخی محیط‌ها prefix دیتابیس با حروف بزرگ/کوچک متفاوت دیده می‌شود. Install با بررسی case-insensitive از خطای «جدول وجود ندارد» جلوگیری می‌کند.

## ۵. جریان اجرا

```text
1. بارگذاری وردپرس
2. پلاگین EzLens Secure Login لود می‌شود
3. فایل‌های ماژول (install / ajax / loader) require می‌شوند
4. Install در صورت نیاز جدول/پوشه را آماده می‌کند
5. در init (اولویت ۲۰):
   Loader رکوردهای status=1 را می‌خواند
   برای هر رکورد:
     - اعتبارسنجی نام فایل
     - بررسی وجود فیزیکی در storage
     - بررسی تداخل نام تابع
     - include_once فایل
6. شورت‌کدها و هوک‌های داخل snippet روی سایت فعال می‌شوند
```

اگر جدول آماده نباشد، Loader متوقف می‌شود و در لاگ پیام می‌نویسد. در نسخه‌های اصلاح‌شده، تلاش خودترمیمی برای ساخت جدول وجود دارد.

## ۶. امنیت

| لایه | توضیح |
|------|--------|
| دسترسی ادمین | فقط کاربران با `manage_options` |
| Nonce | درخواست‌های AJAX با nonce ماژول |
| نام فایل | فقط الگوی امن: حروف، عدد، `-` `_` و پسوند `.php` |
| مسیر storage | جلوگیری از path traversal با `realpath` و پیشوند مسیر |
| `.htaccess` | مسدودسازی اجرای/دسترسی مستقیم وب به storage (بسته به سرور) |
| تداخل تابع | قبل از include، نام توابع اسکن می‌شود؛ در صورت تکراری، فایل غیرفعال می‌شود |

> توجه: کد داخل storage با سطح دسترسی PHP سایت اجرا می‌شود. فقط افراد مورد اعتماد باید به این بخش دسترسی داشته باشند.

## ۸. محدودیت‌ها و ریسک‌ها

1. **Fatal Error یک فایل فعال = اختلال کل سایت**  
   به همین دلیل فعال‌سازی باید بعد از تست باشد.

2. **تداخل نام تابع بین دو فایل فعال**  
   هر دو `function foo()` داشته باشند → خطای redeclare.

3. **include در زمان init**  
   کد سنگین یا کوئری زیاد در هر درخواست، عملکرد را کم می‌کند.

4. **وابستگی به کلاس‌های دیگر**  
   اگر snippet به کلاسی وابسته است که هنوز لود نشده، باید با `class_exists` محافظت شود.
